# 接口契约（后端 API）

> demo 后端：Python + FastAPI + SQLite（`backend/main.py`）。FastAPI 自动生成 OpenAPI，运行后见 `http://localhost:8000/docs`。
> 这里是给前后端 vibe coding 对齐用的速览；字段命名遵循 ../产品文档/glossary.md。

基址：`http://localhost:8000`

## 健康检查
- `GET /api/health` → `{ ok, claude_code: bool, claude_path: string }`
  - `claude_code` 为 true 表示后端能找到 claude，可真实运行调试/试跑

## 项目空间与成员（Spec J/K）
- `GET /api/workspaces` → `[{ id, name, members:[{id,name,role}] }]`
- `POST /api/workspaces` body `{name}` → `{id,name}`（创建者为 owner）
- `PUT /api/workspaces/{ws}/members/{uid}` body `{name, role}` → 增/改成员
- `DELETE /api/workspaces/{ws}/members/{uid}` → 移除（至少保留一名 owner，否则 400）

## Agent 生命周期（Spec A/B/C）
- `GET /api/agents?ws={wsId}` → `[Agent]`（不含软删；每项含 `published`/`publishedVersion`）
- `GET /api/agents/{id}` → `Agent`（含 `versions:[{version,createdAt,config}]` 与 `published`/`publishedVersion`）
- `POST /api/agents` body `AgentIn{ ws_id,name,framework,model,desc,params,files,tools,skills }` → 创建并生成 v1（同空间重名 400）
- `PUT /api/agents/{id}` body `AgentEdit{ model?,desc?,params?,files?,tools?,skills? }` → 生成新版本(+1)
- `DELETE /api/agents/{id}` → 软删除

### Agent 数据结构
```
Agent {
  id, wsId, name, framework, model, desc,
  params: {temperature, max_tokens, ...},   // 数据驱动，来自外部接口
  files: { "claude.md": "..." } | { "role.md","agent.md","user.md" },
  tools: [toolId], skills: [skillId],
  version, updatedAt,
  published, publishedVersion,
  versions: [{version, createdAt, config}]   // 仅详情返回
}
```

## 调试 / 试跑（Spec I）
- `POST /api/agents/{id}/chat` body `{ message, config?, session_id? }` → `{ engine, reply, session_id? }`
  - `config` 传则用未保存配置（调试）；不传则用已保存 agent
  - `session_id` 续接多轮；`engine` ∈ `claude-code | mock | error`
  - 后端无头调用本机 Claude Code：`claude -p … --output-format json [--append-system-prompt …] [--resume …] [--model claude-*]`

## 发布 / Playground（Spec I）
- `POST /api/agents/{id}/publish?version={n}&isolation={L1|L2|L3}` body `{config?}` →
  `{ path, command, files, framework, version, isolation, claude_code }`
  - 带 `config`（编辑页）：有改动先升版本再发布；无改动发布当前
  - 带 `version`（详情页）：发布指定已存在版本，不新增
  - `isolation`=运行环境（隔离级别），默认 `L1`；用户侧用意图文案（共享环境/独立环境/即用即弃），见 架构设计.md §10。**隔离是编排/部署属性，本地 demo 不真正起多沙箱，仅登记。**
  - 物化为本机 Claude Code 工作目录（`claude.md`→`CLAUDE.md`），返回运行命令
- `GET /api/published` → `[{ id,name,framework,model,version,isolation,path,publishedAt,wsId }]`（全部已发布，跨空间）

## 发布即起服务（每 Agent 一服务）
- 发布成功后，后端为该 Agent 启动常驻服务（`agent_runner.py`），`POST /api/agents/{id}/publish` 响应附 **`stable_url`**（对外稳定地址）+ `internal_url`/`service_port`（内部裸端口，见下「稳定寻址」）。`service_url` 为兼容旧字段（= `internal_url`，已不建议对外用）。
- `GET /api/services` → `[{ agentId, name, port, pid, url, version, framework, isolation, gateway?, stable_url, internal_url }]`（在跑的 Agent 服务；**本地单实例**；OpenClaw agent 带 `gateway:true` 且 url/port 同指共享 Gateway）
- `POST /api/agents/{id}/service-chat` body `{ message, session_id? }` → `{ engine, reply, session_id? }`（后端代理到该 Agent 服务的 `/chat`；OpenClaw 自动带 `agent_id` 经共享 Gateway 路由；**稳定路径，调用方不碰端口**；Playground/Chat 用它）
- `POST /api/agents/{id}/service/stop` → 停掉该 Agent 服务（OpenClaw=从共享 Gateway 解绑，不影响同 Gateway 其他 agent）
- `POST /api/services/stop-all` → 停掉**全部** Agent 服务 + 共享 Gateway（含后端重启遗留的孤儿进程，pkill 兜底）→ `{ok, stopped}`
- `GET /api/gateway` → `{ running, port, pid, url, agents:[{agent_id,name,dir,model,version}] }`（OpenClaw 共享 Gateway 运行态 + 当前托管的 agents.list）
- Claude Code Agent 服务自身（`agent_runner.py`，端口 91xx）：`GET /health`（含 `framework`）、`POST /chat`、`POST /chat/stream`
- OpenClaw 共享 Gateway（`openclaw_gateway.py`，端口 91xx）：`GET /health`（含 `openclaw:bool`+`agents`）、`GET/POST /agents`、`DELETE /agents/{id}`、`POST /chat {agent_id,message,session_id?}`、`POST /chat/stream`
- **框架可插拔适配器**（已在 demo 后端实现）：`main.py` `_start_service` 按 `framework` 分派——`CLAUDE_CODE`=每 agent 一进程（`agent_runner.py`，`claude -p`）；`OPENCLAW`=**一个共享 Gateway 托多个 agent**（`openclaw_gateway.py`，按 agentId 路由，发布即热绑定、停服即解绑；未装 openclaw 回退 mock）。新增框架=加一个适配器。

### Agent 服务 API 协议（三种，body 统一 `{message, session_id?}`）
- **协议1 一次性 JSON**（已实现）：`POST /chat` → `{reply, session_id, engine}`
- **协议2 SSE 流式**（已实现）：`POST /chat/stream` → `text/event-stream`，事件 `delta|tool|done|error`；后端代理 `POST /api/agents/{id}/service-chat/stream`
  - 事件示例：`event: delta\ndata: {"text":"…"}` … `event: done\ndata: {"reply":"…","session_id":"…","engine":"claude-code"}`
  - 内部实现：`claude -p --output-format stream-json --include-partial-messages` → 解析 `content_block_delta` 逐字推 `delta`（无增量时回退整段，不重复）；子进程 `stdin=DEVNULL` 避免 3s 等待
- **协议3 异步作业**（⬜后续）：`POST /jobs` → `{job_id}`；`GET /jobs/{id}` 轮询 / webhook（长跑/自治 agent）
- 版本策略：**本地单实例**——重发布新版本会停旧起新（`service-chat` 路径不变，端口可能变；session 绑定实例，换版本不可 resume）。**FC Agent** 走"版本随请求"（后续，不进 SERVICES 注册表）。
- ⬜计划：`service/start|restart`；多版本/灰度（别名 prod/canary）落在 FC/网关层（后续）。

## 对外调用：稳定寻址（强约定，⚠️ 上游必读）
> **对外只用按 id 的网关地址；运行端口是内部细节，永远不要直连。** 否则 agent 一重启/换版本，端口变，上游就得改代码。

- **稳定面（对外契约，绑这个）**
  - 普通 Agent：`POST {后端}/api/agents/{id}/service-chat[/stream]`（按 **agent id** 经网关路由）
  - 通用助手 Copilot：`POST {后端}/api/copilot/chat[/stream]`（按**用户身份**路由——一个用户一个 copilot，跨其所有空间复用）。用户取 `X-User-Id` 头（生产换真实鉴权）；当前空间用 `?ws=` 传，作**上下文**注入消息（不进路由键）。`status/stop` 同样按用户。
  - 响应里的 **`stable_url`** 就是它；唯一会变的稳定点是「后端入口地址」本身（生产用反代/域名固定）。
- **内部面（会变，仅本机调试，勿对外）**：`internal_url` / `service_url` / `port`（裸端口 `127.0.0.1:91xx`，`_free_port` 临时分配，重启/换版本/迁移环境都可能变）。
- **为什么稳**：后端维护注册表 `agentId / user → 当前端点`，收到请求查表转发。重启/换版本/L1→L2/L3 迁移、copilot 从本机进程换成沙箱端点，都只改注册表的解析目标（`_resolve_copilot_endpoint(user)`），**稳定地址不变**——隔离级别与寻址正交（见 架构设计 §10.5）。
- **注册表落库 + 启动对账**（已落地）：`SERVICES` 落 `services` 表；后端启动 `_reconcile_services()`——逐条 `/health` 探活，**仍在跑的进程直接复用**（端口不变、无需重发布），死的清理。即后端重启也能稳定路由，不靠"下次调用懒自愈"。
- **自愈兜底**（已落地）：若注册表条目指向已死端口，`service-chat`/copilot 对话前 `/health` 探测，不通则停旧、重起到新端口再转发；流式下游不可达转成干净 SSE `error`（不抛 ASGI 异常）。
- **健康检查**：每个 Agent 服务/Gateway 暴露 `GET /health`；状态接口（如 `/api/copilot/status`、`/api/services`）以实测可达性为准，不只看注册表是否登记。

## 统一 Session API（对齐业内 Managed Agents 标准：Agent + Environment + Session）
> 参照 Claude Managed Agents / Qoder Cloud Agents：**Session = (Agent + Environment) 的有状态实例，服务端持有历史，按 id 寻址**。`session_id` **单一语义** = 我方会话 id；Claude 续接 token 是纯内部细节。**copilot 与普通 agent 统一走这套**（普通 agent 也有服务端历史）。

- `POST /api/sessions` `{agent, environment_id?, title?}` → `{id, agent, status, ...}`（`agent`='copilot' 或某 agent id；`environment_id` 预留 Phase 2）
- `POST /api/sessions/{id}/events[/stream]` → 发送事件驱动 agent；body 兼容两种：
  - 标准：`{events:[{type:"user.message", content:[{type:"text", text}]}]}`
  - 简写：`{message}`
  - `?stream=true` 或 `/events/stream` 走 SSE（`delta`/`done`/`error`）；后端**每轮原子落库** user+bot 与新续接 token；返回/回显**我方 session id**。
- `GET /api/sessions?agent=` 列表 · `GET /api/sessions/{id}` 详情（含 messages）· `PUT /api/sessions/{id}` 改名 · `DELETE /api/sessions/{id}`
- 数据：`sessions(id,user,agent_ref,environment_ref,title,claude_sid,messages,status,created_at,updated_at)`；`claude_sid`=续接 token（内部）。
- **旧端点 = 薄适配器（不破坏上游）**：`/api/copilot/chat[/stream]`、`/api/copilot/sessions/*` 内部走本套（`agent_ref='copilot'`）；`/api/agents/{id}/service-chat[/stream]` 保留为「调用方自管 session_id（续接 token）」的无状态服务调用。
- **路线（与标准对齐）**：Phase 1 统一 Session（✅已落地）→ Phase 2 Environment 一等资源 → Phase 3 事件状态机（`tool.confirm`/异步任务事件，承载派发）→ Phase 4 对齐细节（session 状态机/archive/vaults/版本钉选）。详见 架构设计 §10.6。

## 服务运行态 vs 发布状态
- 发布状态（持久）：`published` / `publishedVersion`（随 `GET /api/agents`、`GET /api/agents/{id}` 返回）。
- 服务运行态（运行时）：来自 `GET /api/services`（运行中/已停止 + url）。
- 两者都归属 Agent → 列表徽标「已发布 vN · 运行中/已停止」、详情「运行服务」区展示与操作。

## 环境变量（后端）
- `AISPACE_DB` 数据库路径（默认 `backend/aispace.db`）
- `AISPACE_AGENTS_DIR` 发布目录根（默认 `~/aispace-agents`）
- `CLAUDE_BIN` claude 可执行文件全路径（PATH 找不到时用）
- 订阅登录用户**不要**设 `ANTHROPIC_API_KEY`（会改走 API 计费）

## 约定
- 错误用 HTTP 状态码 + `{detail}`（FastAPI 默认）。
- 生产：SQLite→Tablestore；本机运行→云端每用户 sandbox（见 架构设计.md）。
