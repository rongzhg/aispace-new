# 组件库与设计规范

> 共享契约的一部分。目标：让每个人的 AI 都从**同一套现成组件和 token** 里拼界面，而不是各自发明。
> 这样 demo、spec、最终代码天然视觉一致。
>
> 技术栈：React 18 + TypeScript + Ant Design 5。
> **权威视觉规范见根目录 [`视觉规范.dc.html`](../产品文档/视觉规范.dc.html)**（色板/排版/间距/圆角/组件样式的唯一真实来源）；本文件是其工程化落地，token 以视觉规范为准。
> 参考实现见 `demo/`（已按规范落地）。

---

## 1. 技术栈基线

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | React 18 + TypeScript | 严格模式，禁用 `any` |
| UI 库 | Ant Design 5 | 企业级后台组件齐全（分步表单、抽屉、表格、折叠面板都现成） |
| 样式 | AntD Design Token + 少量 CSS-in-JS | 颜色/间距/圆角一律取 token，不写魔法值 |
| 代码编辑器 | Monaco Editor | 配置文件/配置预览的等宽编辑器 |
| 状态 | 组件内 `useState` / 轻量 store | 复杂跨页状态用统一 store，约定见下 |

## 2. 组件使用约定（AI 必须遵守）

- **只用现成组件拼装**：界面元素优先映射到 AntD 组件，不自己手写按钮/输入框/表格。
  - 创建/编辑 Agent → **双栏 Builder**（左配置区 + 右可收起面板：调试/预览），不用 `Steps` 分步
  - Agent 列表 → **高密度行卡片**（可点整卡进详情，悬浮加 1px 软阴影），不用大表格样式
  - 框架切换 → `Segmented`（禁用项 Tooltip）；OpenClaw 多文件 → `Tabs`
  - 工具/技能选择 → `Drawer` + `Input.Search` + `Checkbox`
  - 配置预览 → Builder 右栏 `Tabs` 内的只读代码块（JSON/YAML 切换）
  - 调试/试跑 → 对话窗口组件（Builder 右栏 + 详情 Drawer 复用同一组件）
  - 已选项展示 → `Tag`（强调 `#EEF0FF/#4F46E5`，中性 `#F1F1F4/#5A5C6B`）
  - 模型名/参数/版本号 → 等宽字体码片（`#FAFAFB` 底 + 发丝描边）
  - 锁定状态 → `Tooltip` + 置灰 + `LockOutlined` 图标，`disabled`
- **二次封装放在 `src/components/`**：凡是会复用两次以上的组合（如 FrameworkCard、AssetPickerDrawer），封装成项目组件，其他人/AI 复用它而不是重写。
- **禁止内联魔法值**：颜色、间距、圆角、字号全部走 token（见下）。

## 3. Design Tokens（颜色/间距/字体的唯一来源）

> 与 `视觉规范.dc.html` 一致。改 token 只改这一处，并同步视觉规范。

```ts
// theme.ts —— 全局唯一主题来源（AntD ConfigProvider）
export const theme = {
  token: {
    colorPrimary: '#17171C',   // 墨色 = 主按钮（注意：不是靛蓝）
    colorLink:    '#4F46E5',   // 靛蓝 = 链接/选中/强调，仅此用途
    colorLinkHover: '#6E66EA',
    colorText:    '#17171C',   // 一级文本
    colorTextSecondary: '#5A5C6B',
    colorBorder:  '#E7E7EC',   // 控件描边
    colorBorderSecondary: '#F1F1F5', // 分隔/卡片描边
    colorSuccess: '#34C759',
    colorWarning: '#E6A817',
    colorError:   '#E5484D',
    borderRadius: 8,           // 卡片/面板 8，控件/标签/代码块 6
    fontSize: 14,
    controlHeight: 34,
    fontFamilyCode: 'ui-monospace, SFMono-Regular, Menlo, monospace',
  },
  // 强调浅底/描边（标签等）：#EEF0FF / #DCDFFF
  // 下沉面（侧栏/表头）：#FAFAFB；基础面 #FFFFFF
  spacing: { xs: 4, sm: 8, md: 16, lg: 24, xl: 32 },
};
```

要点（详见视觉规范）：靛蓝**只**用于链接/选中/可点击强调，主按钮用墨色实底无阴影；1px 发丝描边界定结构、阴影仅作轻悬浮反馈；层级靠字重与灰阶不靠字号；语义色仅用于状态。

## 4. 目录与命名约定

```
src/
  components/      # 可复用业务组件（PascalCase 目录，含 .tsx + index.ts）
  pages/           # 页面级（按路由）
  api/             # 接口调用层（按 glossary 实体分文件：agent.ts, tool.ts...）
  types/           # TS 类型（与后端 OpenAPI 对齐，见 完成定义-DoD.md）
  theme.ts         # 唯一主题/token
```
- 组件文件 `PascalCase.tsx`；hooks `useXxx.ts`；类型与 glossary 英文命名一致。
- 一个组件一个职责，超过 ~200 行考虑拆分。

## 5. 视觉规范要点
- 间距只用 token 里那几档，不出现 `margin: 13px` 这种值。
- 状态色统一走 token（成功/警告/错误），不自定义十六进制。
- 禁用/锁定态全站表现一致：置灰 + 不可点 + 必要时图标 + Tooltip 说明原因。
- 空状态、加载态、错误态三件套：列表/表格类组件必须显式处理，不允许"白屏"。

## 6. 黄金样板（Golden Path）
参考实现：**`demo/`**（`app.jsx` 源码 + 编译产物 `index.html`）。已按视觉规范落地了列表行卡片、双栏 Builder、工具/技能抽屉锁定态、版本对比、空间/成员等。
其他功能让 AI "照 demo 的写法做"——AI 模仿现成代码远比理解抽象规范准。
> 注：demo 为纯前端 mock；生产实现须补后端接口契约与测试（见 完成定义-DoD.md），但视觉/交互以 demo 为基准。
