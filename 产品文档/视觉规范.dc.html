Visual system specification

视觉设计风格规范

这是 AISpace 后续所有页面的视觉与交互一致性契约。当前风格定位是专业、高密度、工具化、克制，不做营销式大视觉，不做低密度卡片堆叠。新页面优先复用本规范中的页面骨架、列表模式、工作台模式、会话模式和资源页模式。

01 · Product Character

产品气质与设计原则

AISpace 是给开发者和平台运营者使用的 Agent 工作台。页面第一目标是让用户快速判断状态、定位对象、执行下一步，而不是营造轻松、可爱或品牌展示感。

全局原则
高密度但不拥挤
一屏承载更多可决策信息。列表、表格、工具栏、右侧面板都采用紧凑行高；留白只用于分组和阅读节奏。
克制、硬朗、可控
小圆角、浅背景、发丝描边、少阴影。界面像专业运维工具，而不是营销落地页或低龄化 SaaS。
状态优先
Agent 平台的核心信息是状态、版本、负责人、运行方式。视觉层级必须让 Live、Draft、Runtime、Owner 一眼可见。
操作入口明确
同一动作只保留一个主入口。不要让行点击、文字链接、按钮同时进入同一功能；列表页用显式操作按钮。
应该呈现为
  • 专业控制台，信息紧凑，结构明确。
  • 中性色为主体，蓝色只承担链接、选中和少量强调。
  • 表格和工作台优先，卡片只用于 KPI、面板、重复资源项。
  • 标题克制，靠字重和灰阶做层级。
禁止回到
  • 大号 hero、营销式空话、装饰性插画。
  • 大量渐变、彩色卡片、12px 以上大圆角。
  • 信息堆叠但没有主次判断。
  • 同一功能出现多个入口，或入口文案不说明结果。

04 · Information Density

信息密度与页面结构

页面不是越多信息越好，而是把用户在当前任务中需要判断的主信息排在首屏，次要信息进入 drawer、modal、详情页或二级 meta。

信息取舍
列表页适合展示
  • 对象名称、简短描述、稳定 ID 或框架。
  • 负责人或归属方。
  • 当前业务状态：Live、Runtime、Draft、权限、启用状态。
  • 最后更新或最近活动，作为排序和判断线索。
  • 一到两个明确操作按钮。
列表页不适合展示
  • 不会影响当前选择的大段配置。
  • 模型参数、完整 prompt、长工具说明。
  • 多个相近状态字段，例如 Change、Needs publish 这类含义模糊字段。
  • 强迫用户发布的判断，除非确实是错误或风险。
  • 重复入口，例如行点击和按钮都打开同一页。
页面类型首屏结构信息密度主要操作
运营列表页标题 + KPI 条 + 工具栏 + 表格最高筛选、排序、管理、创建
资源管理页标题 + 工具栏 + 表格/紧凑卡片高上传/注册、启停、查看详情
工作台页顶部对象条 + 左配置 + 右运行/试跑高保存版本、试跑、发布、回滚
会话页标题 + 会话轨 + 主对话区中高新建、切换、输入、技能选择
成员/权限页标题 + 操作条 + 表格中添加、改角色、移除

标签只表达短状态或分类。ID、模型名、端点、版本号使用等宽字体。

表格

表头 11px uppercase，正文 12-13px，行内主信息加粗。默认无斑马纹，依靠发丝分割。操作列固定在右侧，按钮文字必须说明动作。

组件视觉规范交互规范
Drawer白底、1px 左边界、标题 16px/700，内容分区用浅描边。承载版本历史、配置预览、复杂选择；不要用于单个确认。
Modal圆角 6px，标题短，正文直接进入选择控件。用于发布选择、注册资源、危险确认。
Popover只承载轻量解释或小型表单。不要放复杂配置树。
Empty小型空状态，提供下一步按钮或建议。不要在大面积区域只显示“暂无数据”。
Tooltip解释图标按钮或短状态，不替代正文。用户必须不看 tooltip 也能完成主流程。

列表字段规则
  • 必须展示：Agent、Owner、Live、Draft、Action。
  • Agent 单元格包含名称、描述或 id、框架、更新时间。

Chat
平台统一入口。标题区说明当前是否连接后端通用 Agent；左侧会话轨支持新建、切换、重命名、删除。
Playground

会话控制台
偏审计和检索，采用列表 + 详情，不做聊天式输入。按创建人、Agent、状态、时间筛选。

08 · Resource And Admin Pages

部署、Skill、MCP、成员页模式

非 Agent 核心页仍然保持同一套控制台语言。根据任务类型选择表格、紧凑卡片或分栏详情，不要把每个页面做成独立视觉。

Page recipes
页面推荐结构主信息主操作
部署标题 + 运行概览 + 服务表格 + 发布/变更 ModalAgent、稳定地址、Live 版本、部署方式、运行态。管理、停服、重启、变更版本/部署方式。
Skill标题 + 上传/筛选工具栏 + 表格或紧凑资源卡 + 文件树详情名称、来源、描述、启用状态、文件数量、更新时间。上传、查看、启用/禁用、删除。
MCP标题 + 注册工具栏 + 表格 + 详情 Modal名称、命令、分类、来源、启用状态、环境变量要求。注册、查看配置、启用/禁用、删除。
成员与权限标题 + 添加成员条 + 表格成员、角色、空间、最近操作。添加、改角色、移除。
环境状态面板 + 表格/键值列表后端连接、运行引擎、API 状态、沙箱信息。检查、复制、清理。
资源页资源卡
只有当资源说明需要多行阅读时使用卡片。卡片圆角 6px、边框 #DFE3EA、padding 12px，不要放大图标和装饰色块。
资源页表格
当资源超过 6 个或需要筛选排序时优先表格。操作列固定右侧，危险操作进入 Popconfirm。
09 · State And Feedback

状态、反馈与微交互

状态文案要说明事实和下一步，不要只给颜色。失败要展示错误原因，部署中要说明预计耗时或轮询状态。

Runtime states
未发布
无 Live。提供“发布 vN”而不是“启动”。
运行中
显示 Live 版本、部署方式、稳定地址。
部署中
禁用重复操作，显示自动刷新或预计耗时。
失败
展示错误原因，提供重新发布或查看详情。
场景反馈方式文案要求
保存成功message.success“已保存为 v3”，必须包含版本结果。
发布成功message.success + 右侧状态刷新“已发布 v3 · 共享 L1”，必须包含 Live 和部署方式。
未保存改动禁用发布按钮 + inline hint“先保存为新版本，再选择是否发布”。
回滚Modal/Drawer 明确两条路径区分“回滚为新版本”和“直接发布历史版本”。
删除Popconfirm说明是软删除还是永久删除。
后端不可用页面 subtitle 或状态 tag说明“未连后端 · 本地 mock”，不要静默假装真实。
10 · Implementation Checklist

新页面落地检查清单

每做一个新页面或大改一个页面，按这个清单过一遍。SPEC 决定做什么，本文件决定看起来和交互方式是否一致。

DoD for UI
视觉检查
  • 页面是否使用统一 Shell：236px 侧栏、48px 顶栏、#F6F7F9 内容底。
  • 是否只使用 tokens 中的颜色、圆角、字号。
  • 是否避免大圆角、大阴影、大面积蓝色、营销式标题。
  • 表格、工具栏、面板是否保持高密度。
  • 文本是否没有溢出、重叠、被按钮挤压。
交互检查
  • 一个功能是否只有一个清晰主入口。
  • 主操作是否写明结果，例如“发布 v3”而不是“发布”。
  • 空状态是否给出下一步，而不是只写“暂无”。
  • 危险操作是否二次确认。
  • 移动或窄屏下是否变为单列，不出现横向挤压。
和 SPEC 的关系
功能字段、流程、状态语义以 `产品文档/specs/` 为准；视觉层级、组件样式、页面骨架以本文件为准。如果实现时发现 SPEC 需要一个新页面模式，先补本视觉规范，再写代码。
